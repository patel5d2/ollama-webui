# LLM hosting experiment

The saved plan is PLAN.md, fixed inputs are prompts.json, and run.py measures real Ollama API responses. Raw results are under results/ with a CSV, hardware output, settings, model metadata, and complete responses for each successful suite.

Environments: own Mac (Docker CPU and native Apple GPU), Google Colab free T4, and a Jetstream2 VM with an A100 vGPU (added 2026-10-12, see NOTES.md for the GPU-permission fix).

## Repeat local CPU runs

From the project root, with Docker Desktop running:

```sh
docker compose up -d
python3 experiment/run.py --environment local-docker-cpu
python3 experiment/run.py --environment local-docker-cpu --models qwen3:1.7b --settings
```

Open http://localhost:3000 for Open WebUI. Select a named local model before sending a prompt. A GUI response is evidence of interaction; its default parameters are not guaranteed to match run.py.

## Repeat native Apple GPU runs

Native Ollama was downloaded from https://ollama.com/download/Ollama-darwin.zip and extracted inside experiment/native. Start in a separate terminal:

```sh
OLLAMA_HOST=127.0.0.1:11435 OLLAMA_MODELS="$PWD/experiment/native-models" experiment/native/Ollama.app/Contents/Resources/ollama serve
```

Then:

```sh
python3 experiment/run.py --environment local-metal-gpu --url http://127.0.0.1:11435
```

The GPU is verified by the saved resident model VRAM allocation and native-server.log; Docker allocation is zero GPU bytes.

## Jetstream2

On the VM (web desktop terminal), with run.py and prompts.json copied next to each other:

```sh
curl -fsSL https://ollama.com/install.sh | sh
sudo usermod -aG vglusers ollama && sudo systemctl restart ollama   # otherwise Ollama silently uses the CPU
ollama ps                                                         # must say 100% GPU while a model is loaded
python3 run.py --environment jetstream2-a100
python3 run.py --environment jetstream2-a100 --models qwen3:1.7b --settings
python3 run.py --environment jetstream2-a100 --models qwen3:14b qwen3:32b
```

Shelve the instance in Exosphere when finished; it spends the class allocation while running.

## Measurement interpretation

Answer seconds are end-to-end non-streaming request time. Tokens/s uses the server's generated token count divided by generation duration. Load seconds are the empty-prompt load request wall time. Memory is a post-response model allocation snapshot, not peak RSS or system memory. Models are unloaded between suites; OS file caches are not cleared. Identical settings do not guarantee identical token sequences across backends or versions.

Read NOTES.md before using the results. VIDEO_GUIDE.md is an outline for your own 5-10 minute narrated live recording. Do not claim assistant-operated runs were performed unaided.
